# DECISION_LOG.md — 결정 기록

> **목적**: "왜 그렇게 했더라?"에 답하는 문서. 기술 선택·아키텍처·트레이드오프가 있는
> 결정을 기록한다. 과거 결정을 뒤집기 전에 반드시 여기서 당시 이유를 확인한다.
>
> **기록 대상**: 스택·라이브러리 선택, 구조 결정, 데이터 모델 설계, 버리기로 한 대안,
> 보안/성능 트레이드오프. (사소한 네이밍·스타일 결정은 기록하지 않는다)
>
> **작성 규칙**: 최신 항목을 맨 위에 추가(append-only). 과거 항목은 수정하지 않고,
> 뒤집을 때는 새 항목으로 기록하고 이전 항목에 `→ D-XXX로 대체됨`만 표시한다.

---

## 템플릿

```markdown
## D-001 | YYYY-MM-DD | 결정 제목
- **상태**: 채택 / 대체됨(→ D-XXX)
- **맥락**: 어떤 상황에서 어떤 문제를 풀어야 했는가 (1~3줄)
- **결정**: 무엇을 하기로 했는가 (1줄)
- **이유**: 왜 이것인가 (1~3줄)
- **버린 대안**: 대안 A — 버린 이유 / 대안 B — 버린 이유
- **영향/제약**: 이 결정으로 생기는 제약이나 후속 작업 (없으면 생략)
```

## D-001 | 2026-11-20 | 실행기 = 운영 사이트 하나를 띄우는 얇은 껍데기
- **상태**: 채택
- **맥락**: PC 클라이언트가 필요하지만 실행기 화면·소식이 바뀔 때마다 exe 를 다시 받게 하고 싶지 않다(사이트 C2_BRIEF 1절).
- **결정**: 실행기 화면도 사이트(`/#/launcher`)가 그리고, 껍데기는 창 · 실행기 주소 · 다리 · 새 판 받기만 한다.
- **이유**: 화면 고침이 사이트 배포 한 번으로 끝난다. 껍데기 코드가 작아 보안 검토 면이 좁다.
- **버린 대안**: 실행기 화면을 껍데기에 내장 — 고칠 때마다 새 판 배포가 필요.
- **영향/제약**: 다리 이름(`BRIDGE_FNS`)은 두 저장소가 같아야 한다(`tests/bridge.test.cjs`). sandbox preload 는 electron 밖 파일을 못 불러 통로 이름을 preload 에 한 번 더 적고, 같은지 시험이 본다.
